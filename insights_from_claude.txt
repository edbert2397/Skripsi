  B. WHY NO-REPLAY CAN BE BETTER (and How to Frame It)

  Your observation (no-replay > with-replay) is actually publishable-quality insight. Possible explanations:

  1. Replay introduces gradient conflict: When replay batch is small (4 samples) relative to current batch (15), the
  mixed gradient can be noisy and fight against the orthogonal projection direction.
  2. Orthogonal projection already prevents forgetting: If hard projection is strong enough, replay becomes redundant
  noise.
  3. IPC freezing + projection is sufficient: The combination of freezing critical neurons + projecting gradients into
  null-space makes replay unnecessary.

  How to frame in thesis:
  "DLOG's orthogonal gating mechanism alone achieves competitive anti-forgetting without requiring experience replay,
  thus eliminating memory overhead for storing past examples — a significant advantage for privacy-sensitive and
  memory-constrained deployments."

  This is actually a strength, not a weakness!

  C. CONCRETE IMPROVEMENTS TO TRY (Pick 2-3)

  C1. EMA Consolidation (from SuRe paper) — Easy, ~1 day

  Instead of only updating Slow at task boundaries via QR+SVD, add periodic EMA during training:
  θ_slow ← α · θ_slow + (1 - α) · θ_fast   (every N steps)
  The https://arxiv.org/abs/2511.22367 shows this gives +5pp over hard boundary consolidation. You can try:
  - α = 0.99 or 0.999
  - Apply every 50 or 100 steps
  - Still do QR+SVD at task boundary for compression

  Caveat: If you do EMA during training, the null-space changes every update, which complicates hard projection. One
  option: only EMA the Slow weights but recompute projection basis after each EMA step (expensive), or only do EMA for
  the last 30% of steps per task.

  C2. Surprise-Based Replay Selection — Easy, ~1 day

  Replace reservoir sampling with NLL-based prioritization:
  # When adding to buffer, compute NLL
  nll = -log_prob(sample)
  # Store (sample, nll) and keep top-K highest NLL samples
  High-surprise (high-NLL) samples are the ones the model is most at risk of forgetting. This is much better than random
   reservoir sampling with almost no code change.

  C3. Adaptive λ_orth — Easy, ~0.5 day

  Instead of fixed λ_orth = 0.01, scale it based on task index:
  lambda_orth = base_lambda * (1 + task_idx * 0.5)
  Rationale: As more tasks are learned, the Slow space grows and needs stronger protection. Literature supports this
  (curriculum-style regularization).

  C4. Try Different Projection Targets — Medium, ~1 day

  Your code supports both "parameter" and "memory_gradient" projection. Compare them! The memory-gradient mode uses
  actual replay gradients to define the protected subspace, which can be more accurate than the Slow parameter
  null-space. This is a good ablation to include.

  C5. Vary Replay Ratio Systematically — Easy, ~3 nights

  Run: replay_ratio ∈ {0, 0.05, 0.10, 0.15, 0.20}. Plot the curve of FP vs replay_ratio. If there's a sweet spot (or if
  0 is best), that's a strong finding.

  C6. Task Order Robustness — Easy, ~2 nights

  Run at least 2 different task orders:
  - Current: SST-2 → AG News → Amazon → DBPedia
  - Reversed: DBPedia → Amazon → AG News → SST-2
  - Random: AG News → SST-2 → DBPedia → Amazon

  Showing DLOG is robust to task order is a strong selling point.

  F. PRACTICAL TIPS

  1. Always report BWT and Forgetting, not just accuracy. DLOG's advantage shows most in anti-forgetting metrics, even
  when final accuracy is similar.
  2. Use the performance matrix (the task×task grid). It visually shows which tasks are forgotten. Very compelling in a
  thesis.
  3. Report training time and parameter overhead. Show the projection overhead is small (you already have this at
  ~5-13%).
  4. 3 random seeds minimum for your main results table. Without variance estimates, reviewers can't trust single-run
  numbers.
  5. If DLOG ≈ Baseline on 1.5B, the argument is: "DLOG achieves comparable accuracy with principled forgetting
  prevention rather than relying purely on replay." Or run on harder benchmarks where the gap widens.
  6. Consider adding one more challenging task to the sequence (e.g., MNLI, QNLI, or Yelp) to make the 4-task sequence
  harder. More tasks = more forgetting = DLOG's mechanisms shine more.
  7. Log everything. Save all configs, metrics, and model checkpoints. You'll thank yourself when writing.
